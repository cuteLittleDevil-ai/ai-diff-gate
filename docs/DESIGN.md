## 1. 设计目标与原则

### 1.1 设计目标

在满足 PRD 中 P0 能力（协议适配、fan-out、文本 Diff、HTML 并排、配置驱动）的前提下，让 Demo 代码：

- 结构清晰，新增一家厂商适配时主要改 `adapter`，少动主流程。
- 本地可一键启动，依赖面可控。
- 行为可预期；未拍板项以「建议默认」落在 SPEC，实现时再确认。

### 1.2 原则

| 原则 | 含义 |
|------|------|
| 适配与编排分离 | 厂商协议细节进 adapter；fanout / compare / handler 只依赖统一 Provider 抽象 |
| 同步优先 | MVP 走请求-响应；SSE 作为扩展点预留，不阻塞主路径 |
| 配置驱动 | 模型列表、endpoint、鉴权相关项来自配置，而非硬编码 |
| 建议未拍板不写成事实 | HTTP 框架、失败语义、Diff 粒度、是否兼容代理等一律「建议 + 选项 + 待确认」 |

## 2. 逻辑架构与请求流程

### 2.1 逻辑分层

```
┌─────────────────────────────────────────┐
│  Web（HTML） / 可选 JSON 调用方          │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│  Handler：解析请求、组装对比集、渲染结果  │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│  Fanout：并发调用多个 Provider、汇总结果 │
└───────────────────┬─────────────────────┘
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
   Provider A  Provider B  Provider C
   (adapter)   (adapter)   (adapter)
        │           │           │
        ▼           ▼           ▼
   上游模型 API（OpenAI / Anthropic / …）
                    │
┌───────────────────▼─────────────────────┐
│  Compare：文本 Diff（+ 可选指标汇总）    │
└───────────────────┬─────────────────────┘
                    │
              HTML / 可选 JSON
```

### 2.2 请求流程（同步 MVP）

```
客户端 / HTML
    ↓
Handler（接收 Prompt 与模型选择）
    ↓
Fanout（按超时与失败策略并发调用多个 Provider）
    ↓
Adapter（内部 ChatRequest → 厂商协议 → ChatResponse）
    ↓
各上游模型
    ↓
结果汇总 + Diff 计算
    ↓
HTML 渲染（及可选 JSON 返回）
```

是否同时提供 JSON API、失败时是否仍渲染成功子集，见第 8 节与开放问题 Q1、Q3。

## 4. 核心接口思路（Provider）

统一抽象（示意，非最终签名）：

```go
type Provider interface {
    Name() string
    Chat(ctx context.Context, req *ChatRequest) (*ChatResponse, error)
}
```

要点：

- `ChatRequest` / `ChatResponse` 为**内部**归一化结构，由 adapter 负责与厂商协议互转。
- Fanout 只依赖 `Provider`，不感知 OpenAI / Anthropic 细节。
- 字段建议与必填/可选约定见 SPEC；此处不展开 JSON schema。

## 5. 模块职责

| 模块 | 职责 | 不负责 |
|------|------|--------|
| `adapter` | 厂商鉴权头、请求体转换、响应解析、错误映射 | 并发策略、Diff、页面渲染 |
| `provider` | 接口定义、内部请求/响应类型、（可选）注册/查找 | 具体 HTTP 调用细节可下沉 adapter |
| `fanout` | 并发调用、超时传播、部分失败汇总 | 协议细节、Diff 算法 |
| `compare` | 文本 Diff、（可选）延迟/token 汇总展示数据 | 上游调用 |
| `handler` | HTTP 入口、参数校验、调用 fanout/compare、返回 HTML/JSON | 厂商协议 |
| `web` | 静态或内嵌 HTML：输入区、结果并排、Diff 展示 | 业务逻辑 |

## 6. 技术选型表

**标注「Demo 建议，未最终拍板」的项，实现前需确认。**

| 类别 | 建议 | 选项 | 状态 |
|------|------|------|------|
| 语言 | Go | — | 与作者主力语言一致，倾向采用 |

## 8. 扩展点

| 扩展点 | 接入方式（建议） |
|--------|------------------|
| 新厂商（Gemini、DeepSeek、本地） | 新增 adapter，实现 Provider；配置增加条目 |
| SSE | Handler / Provider 增加流式路径；fanout 与 compare 需定义「流式对比」语义后再做 |
| 语义相似度 | 在 `compare` 旁增加可选打分模块，不替换文本 Diff |
| 更好 UI / 历史 | 替换或增强 `web/`；历史需持久化选型（本阶段不做） |

## 9. 已知设计取舍与待拍板项

### 9.1 取舍（当前倾向）

| 主题 | 当前倾向 | 代价 |
|------|----------|------|
| 同步 vs 流式 | MVP 同步 | 慢模型时等待感强 |
| Demo vs 生产 | Demo | 无 HA、无计费、无完整安全体系 |
| 文本 Diff vs 语义 | MVP 文本 | 语义差异需另模块 |

### 9.2 必须写成「建议 + 选项 + 待确认」的项

| 编号 | 主题 | 建议 | 选项 | 待确认 |
|------|------|------|------|--------|
| D1 / Q1 | 部分失败与超时 | 成功子集仍展示，失败模型标错；单模型超时建议默认 60s | 整单失败；更短/更长超时 | 产品 + 实现 |
| D2 / Q2 | Diff 粒度 | 建议默认按行；空白是否折叠待定 | 词级 / 段级 | 产品体验 |
| D3 / Q3 | HTML vs JSON | 建议 MVP HTML 必做，JSON 同步支持成本低可一并做 | 仅 HTML | 产品 |
| D4 / Q4 | 模型选择 | 建议配置声明可用模型，页面可勾选子集 | 配置写死本轮集合 | 产品 |
| D5 / Q5 | Key 存放 | 建议 YAML 引用环境变量，避免明文入库 | 明文 YAML / `.env` | 安全习惯 |
| D6 / Q6 | 透明代理 vs 对比 API | 建议 MVP 做**对比专用入口**，不做完整 OpenAI 兼容代理 | 兼容代理 | 产品定位 |
| D7 | HTTP 框架 | 建议标准库起步 | Gin / Fiber | 实现偏好 |

字段级默认值与验收用例见 `docs/SPEC.md`。
